# sctl Browser 第 5 期：原始 CDP

<!-- File: docs/specs/2026-10-08-raw-cdp.md -->

> Status: Approved
> Owner: sctl maintainers
> Last updated: 2026-10-09

**目标：** AI agent 和 shell 脚本可以通过 sctl 命令行和 MCP，向用户浏览器里的某个标签页发送单条原始 CDP 命令；也可以拿到一个 CDP 端点，让现有的 Playwright（`connectOverCDP`）和 Puppeteer（`connect`）脚本直接驱动用户正在使用的浏览器。

**不可退化的约束：**

- 第 1–4 期的全部行为不变（ScriptCat 的连接和 `scripts.*`、浏览器数据管理、页面自动化、调试的命令、MCP 工具和退出码），只有本 spec 明确写出的「端点有客户端连着时」例外。
- 给 ScriptCat 的生成 TS 文件保持逐字节不变。

本期是五期规划的最后一期，依赖第 3 期的 CDP 中转与第 4 期的附加流程（都已合并）。

## 问题

1. **sctl 只能用自己封装好的动作操作页面。** 已验证。第 3 期把 CDP 中转方法标成 internal，不对 `/control/call` 和 MCP 开放，CLI 也不提供原始命令（第 3 期 spec「中转方法不对 MCP 直接暴露」一条与「不在本期范围」；`internal/daemon/controlapi/controlapi.go` 对 internal 方法回答 unknown action，`internal/client/mcpserver/mcpserver.go` 注册工具时跳过它们）。快照、点击、调试记录之外的需求（例如打印 PDF、改设备尺寸、拦截请求、读性能指标）现在无路可走。
2. **现有的 Playwright / Puppeteer 脚本用不上用户的浏览器。** 已验证。这两个库要连一个浏览器级的 CDP 端点；sctl 没有面向客户端的 WebSocket 端点，daemon 上唯一的 WebSocket 是给扩展的（`internal/daemon/bridge/server.go`）。用户的浏览器没有以远程调试端口启动，`chrome.debugger` 也只能附加到标签页，不能附加到浏览器本身（真机探针：在标签页会话上 `Target.getTargets` 返回 "Not allowed"）。

## 角色与用户故事

1. 作为通过 `sctl mcp` 接入的 AI agent，我希望对某个标签页发一条 sctl 没有封装的 CDP 命令（如 `Page.printToPDF`、`Emulation.setDeviceMetricsOverride`），这样不用等 sctl 加新命令。
2. 作为写自动化脚本的开发者，我希望把已有的 Playwright 或 Puppeteer 脚本指向一个 sctl 给的地址，就能在用户已登录的浏览器里运行，这样不用另开一个干净的浏览器重新登录。
3. 作为 AI agent，我希望拿到端点地址后自己写一段 Playwright 脚本完成复杂流程，再交还给 sctl 的命令继续工作。

## 设计决策

| # | 决策 | 依据与被否方案 |
|---|---|---|
| 1 | 同时提供单条原始命令（A）和给 Playwright/Puppeteer 的端点（B）。 | 用户决定。两者互不依赖，A 小而稳，B 满足现有脚本。被否：只做其一。 |
| 2 | 端点在 sctl 侧模拟浏览器级目标，会话级命令转发到对应标签页。 | 真机探针：`chrome.debugger` 只能附加标签页，浏览器级的 `Target.*`、`Browser.*` 在标签页会话上被拒绝；Playwright 自己的扩展中转（playwright-core 1.64）也是这样做的。被否：要求用户以 `--remote-debugging-port` 重启浏览器——失去「用用户正在用的浏览器」这一点。 |
| 3 | 端点暴露这个浏览器里所有能附加的标签页。 | 用户决定。被否：只暴露指定的标签页和客户端自己打开的——用户选择让脚本看到全部。 |
| 4 | 每个标签页同一时刻只有一个使用方：端点有客户端连着时，这个浏览器的标签页都归端点，sctl 自己的页面、调试和原始命令对它们返回 `ENDPOINT_CONNECTED`；客户端断开后恢复。 | 用户决定。一个扩展对一个标签页只能附加一次，所有使用方共用同一个调试会话；CDP 的域开关作用于整个会话，后来者开启已开着的域收不到初始状态，任一方关闭会影响其他方（真机探针：Playwright 收不到 console、`evaluate` 挂起）。被否：做共享层为每个使用方模拟独立会话——探针中 Chromium 153 有界面 + Puppeteer 后加入仍失败，工作量和风险都大。 |
| 5 | 端点地址本身就是凭据：持有控制令牌的命令创建它，地址里带不可猜的随机密钥，客户端不需要额外的头。 | 用户决定。很多工具只接受一个 URL。被否：连接时要求控制令牌头——许多工具无法设置。 |
| 6 | 每个浏览器同时只有一个端点、只允许一个客户端连着；地址可重复连接，`sctl cdp close`、daemon 退出、或连续 60 分钟没有客户端连着时失效。 | 用户决定。暴露全部标签页时两个客户端会共用同一批会话、互相破坏。被否：用一次就失效——每次都要重新创建。 |
| 7 | 客户端断开或调用 `browser.close()` 后，只断开调试器，标签页（包括客户端自己打开的）都保留。 | 用户决定。这是用户的浏览器，不替用户关页面。被否：断开时关掉客户端打开的标签页。 |
| 8 | 原始命令走 sctl 自己的调试会话，与页面和调试命令共用附加与串行规则；拒绝会破坏 sctl 自身状态的少数命令，其余（包括会让请求挂住的 `Fetch.enable`、会让页面停住的 `Debugger.pause`）放行并在帮助中写明后果。 | 用户决定。被否：全部放行、只在文档里警告——一条 `Runtime.disable` 就会让调试记录静默停止；把 `Fetch.enable`、`Debugger.pause` 也拒绝——有人就是要暂停后再恢复或手动处理请求，原始命令应保持原始。 |
| 9 | MCP 提供 `cdp_send`、`cdp_endpoint`、`cdp_close`。 | 用户决定。AI 既能发单条命令，也能拿到端点去运行脚本。被否：只有命令行。 |

## 原始命令

- **发送：**
  - *操作：* `sctl cdp send <Method> [--params '<JSON 对象>'] [--tab N] [--browser B] [--timeout D]`；MCP 工具 `cdp_send`，参数 `method`、`params`、`tabId`、`browser`、`timeoutMs`。
  - *结果：* 对目标标签页的顶层页面发送这条命令，返回 Chrome 的原始结果对象，外加 `tabId` 和 `contentTrust: "untrusted-page-content"`。命令行默认输出缩进的 JSON。
  - 目标选择、附加、空闲断开、串行规则与第 3 期页面命令相同：标签页未附加时先附加；同一标签页上与页面、调试命令排队执行。默认超时 10 秒。
  - 只发给顶层页面；跨进程 iframe 的子会话不在范围内。命令产生的 CDP 事件不返回。
- **校验与错误：**
  - `<Method>` 必须形如 `Domain.method`；`--params` 必须是 JSON 对象。否则返回 `INVALID_REQUEST`，退出码 3。
  - Chrome 拒绝或不认识这条命令时返回 `INVALID_REQUEST`，带 Chrome 自己的错误信息。
  - 结果超过单帧上限（4 MiB）返回 `PAYLOAD_TOO_LARGE`；超时返回 `TIMEOUT`。
- **拒绝的命令：** 以下命令会破坏 sctl 自身的状态，直接返回 `INVALID_REQUEST` 并说明原因，不发给 Chrome：
  - `Page.disable`、`Runtime.disable`、`Network.disable`、`Log.disable`（sctl 的页面自动化与调试记录依赖它们开着）；
  - `Emulation.setFocusEmulationEnabled`（后台标签页上的操作依赖焦点模拟）；
  - `Target.setAutoAttach`、`Target.detachFromTarget`（sctl 靠它们发现、暂停并放行跨进程 iframe）。
- **其余命令的副作用由调用方负责：** 拒绝列表之外的命令原样发送。会持续生效的设置（如 `Emulation.setDeviceMetricsOverride`、`Network.setExtraHTTPHeaders`）会影响之后的页面命令，直到调用方自己恢复。由于原始命令不返回事件，`Fetch.enable` 之后没有人处理被暂停的请求，标签页上的请求都会挂住；`Debugger.enable` 加 `Debugger.pause` 会让页面停住。命令行帮助和 MCP 工具描述写明这些后果与恢复办法：发送对应的 `Fetch.disable`、`Debugger.resume`，或 `page detach` 后重新附加。
- **JS 弹框：** 原始命令不检查弹框，标签页上有未处理的弹框时照常发送，所以可以用它发送 `Page.handleJavaScriptDialog`。弹框期间 Chrome 会阻塞的命令会等到超时。
- **端点有客户端连着时：** 返回 `ENDPOINT_CONNECTED`（见下）。

## CDP 端点

### 创建、查看与关闭

- **创建：**
  - *操作：* `sctl cdp endpoint [--browser B]`；MCP `cdp_endpoint`。
  - *结果：* 这个浏览器还没有端点时创建一个；已有时返回同一个。输出两种地址：
    - `http://<daemon 地址>/cdp/<密钥>`：给 Playwright `chromium.connectOverCDP()`；
    - `ws://<daemon 地址>/cdp/<密钥>/devtools/browser/<id>`：给 Puppeteer `connect({ browserWSEndpoint })`。
    同时给出是否有客户端连着、何时失效。
  - 浏览器未连接时返回第 1 期的 `BROWSER_OFFLINE` / `NO_BROWSER_CONNECTED`。
- **查看：** `sctl cdp status [--browser B]` 列出端点的地址、是否有客户端连着、连上的时间、失效时间；没有端点时如实说明。MCP 的 `cdp_endpoint` 同时承担查看。
- **关闭：** `sctl cdp close [--browser B]`；MCP `cdp_close`。地址立即失效；有客户端连着时断开它（处理同「客户端断开」）。没有端点时也成功。
- **失效：** 以下任一情况地址失效，之后连接被拒绝：`sctl cdp close`；daemon 退出；端点连续 60 分钟没有客户端连着；这个浏览器实例被 `sctl browsers forget` 遗忘。客户端断开后，地址在失效前可以再次连接。
- **单客户端：** 已有客户端连着时，第二个连接被拒绝，响应说明已有客户端在用。

### 连上之后

- **连接时：** sctl 先断开自己在这个浏览器里附加的所有标签页（结束录制、清空调试缓存、先关闭已知的弹框，同第 4 期的断开规则），然后把标签页交给端点。
- **可见的标签页：** 这个浏览器里所有能附加的标签页；`chrome://`、扩展页面、应用商店等不能附加的页面不出现。客户端连着期间用户或页面新打开的标签页也会出现。客户端附加的每个标签页都会显示 Chrome 的调试提示条。
- **焦点模拟：** 端点附加的标签页都开启焦点模拟，后台标签页上的点击、输入、弹框和截图与前台一致（真机探针：Puppeteer 不开焦点模拟时在后台标签页上超时）。
- **浏览器级命令：** 由 sctl 模拟，客户端看到的是一个浏览器：浏览器版本（真实的 User-Agent）、目标的发现与附加、目标信息、新建目标（在这个浏览器里打开新标签页）、关闭目标（关闭那个标签页）、激活目标，以及目标的创建、变化、销毁、附加、分离事件。`Browser.close` 只断开客户端，不关闭浏览器。设置下载行为的请求（Playwright 连接时一定会发）成功但不起作用：下载按浏览器自己的设置进行，客户端收不到下载事件。
- **会话级命令：** 原样转发到对应标签页，包括跨进程 iframe 的子会话；事件原样转回。
- **不支持的功能：** 下载事件收不到（见上）；以下请求返回 CDP 错误，说明 sctl 的端点不支持：新的浏览器上下文（Playwright `browser.newContext()`、Puppeteer `createBrowserContext()`）、权限授予、窗口尺寸、忽略证书错误、Service Worker 目标。Chrome 125 上读取 Cookie 被 Chrome 拒绝（153 可以），错误原样返回。
- **sctl 自己的命令：** 客户端连着时，对这个浏览器标签页的 `page`、`debug`、`cdp send` 命令返回 `ENDPOINT_CONNECTED`，退出码 3，说明有端点客户端在用、可以断开客户端或执行 `sctl cdp close`。不操作页面的命令（`tabs`、`windows`、书签等第 1–2 期命令）照常执行。

### 断开

- **客户端断开**（包括 `browser.close()`、网络断开、`sctl cdp close`）：sctl 先关闭端点标签页上已知的 JS 弹框，再断开所有端点附加的标签页；标签页本身（包括客户端新打开的）都保留。之后 sctl 自己的命令恢复可用。
- **浏览器实例断开或 daemon 退出：** 客户端连接被关闭。

## 安全与隐私

- 端点给出对这个浏览器全部标签页不经审批的完整控制，包括读取页面内容、Cookie（Chrome 允许时）、执行脚本、发起请求。这一点写进威胁模型，与第 3 期页面自动化放在一起。
- 只有持有控制令牌的进程能创建端点。地址里的密钥至少 128 位随机数，只存在 daemon 内存里，不写盘；`close` 或 daemon 重启后旧地址失效。
- 防止网页滥用与 DNS 重绑定：端点拒绝 Host 不是回环地址或 IP 字面量的请求，以及带有网页 Origin 的 WebSocket 请求。
- daemon 默认只监听 127.0.0.1；用 `--listen-address` 绑定其他网卡时，端点也能从网络上访问，持有地址的人即可完全控制浏览器——文档写明。
- 原始命令与端点的结果都由网页控制，作为数据返回，结果带 `contentTrust` 标记（端点上的 CDP 消息原样转发，不加标记）。

## 协议与权限

- 不新增浏览器权限，`minimum_chrome_version` 仍为 125。
- 扩展需要能为端点列出能附加的标签页（含 DevTools 目标 ID）、给出浏览器真实的 User-Agent、打开和关闭标签页，并报告标签页的创建、变化与关闭；这些都是只供 daemon 调用的内部方法或通知，先加进 `protocol.json`，再按对端生成代码；给 ScriptCat 的生成文件逐字节不变。
- 新错误码 `ENDPOINT_CONNECTED` 只对浏览器扩展这一对端生成。

## 真机探针的结论

在隔离配置中用 Chrome for Testing 125.0.6422.141 与 Chromium 153，headless 与有界面，用一次性扩展加 node 中转做了原型，证据在 `.dev-kit/artifacts/2026-10-08-raw-cdp/probe/`（已 gitignore）。

- Playwright `connectOverCDP`：连接、列出已有页面、导航、执行脚本、填写与点击、截图、跨源 iframe、console 与请求事件、弹框、`page.route`、popup、新建与关闭页面、`browser.close` 不关浏览器，在所有配置下都通过，包括后台标签页。
- Puppeteer `connect`：开启焦点模拟后除不支持项外全部通过；不开时后台标签页上的点击、输入、弹框、popup 超时，125 上截图挂起。
- 标签页会话上被拒绝的命令：浏览器级 `Target.*` 发现与附加、所有 `Browser.*`、`SystemInfo.*`、`Security.*`、`HeapProfiler.*`、`Memory.*`、`ServiceWorker.*`；`Target.createTarget` 允许（会打开新标签页）。Cookie 读取在 125 上被拒、153 允许。
- 共用同一个扩展的附加时，各使用方共享域状态（见设计决策 4）；另一个扩展独立附加同一标签页互不影响。
- 浏览器启动后从未显示过的后台标签页，最初几条命令可能卡 7–30 秒；一次因此连接超时。

## 不在本期范围

- 多个客户端共享同一个标签页，或 sctl 命令与端点客户端同时使用同一个浏览器的标签页（设计决策 4）。
- 新的浏览器上下文、权限、下载事件、窗口尺寸、证书错误、Service Worker（见「不支持的功能」）。
- 原始命令发给跨进程 iframe 子会话、原始命令返回事件流。
- Firefox、Safari。

## 未决问题
